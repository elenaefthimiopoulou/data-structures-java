# Εργασία 1 - Δομές Δεδομένων

## Υλοποιήσεις ΑΤΔ και εφαρμογές

Σκοπός της εργασίας αυτής είναι η εξοικείωση με βασικούς αφηρημένους τύπους δεδομένων όπως οι στοίβες και οι ουρές FIFO, η εφαρμογή τους σε πρακτικά προβλήματα, και η οργάνωση του κώδικα σε μια πρότυπη αρχιτεκτονική Java.

## Μέρος Α: Υλοποίηση Στοίβας (Stack) και Ουράς (Queue)

### Στόχος

Ο στόχος του Μέρους Α είναι η υλοποίηση των δομών δεδομένων της Στοίβας και της Ουράς, χρησιμοποιώντας ως βάση μια δομή Μονής Συνδεδεμένης Λίστας (Single Linked List).
Συγκεκριμένα, σας δίνονται οι διεπαφές `Stack.java`, `Queue.java` και το πακέτο `list`, το οποίο περιέχει την υλοποίηση του `Node.java`, την διεπαφή `List.java` και την μερική υλοποίηση της διεπαφής `ListImpl.java` (η οποία περιέχει την υλοποίηση της `toString()`). 
Εσείς θα πρέπει να ολοκληρώσετε πρώτα την υλοποίηση της διεπαφής της Λίστας και στη συνέχεια να υλοποιήσετε τις διεπαφές της Στοίβας και της Ουράς.
Η διεπαφή της Λίστας μοιάζει πολύ με αυτήν που είδαμε στο εργαστήριο.
Ιδιαίτερη έμφαση πρέπει να δοθεί στην αποδοτικότητα των υλοποιήσεων, με όλες τις βασικές λειτουργίες να έχουν πολυπλοκότητα **O(1)**.

Μπορείτε να βρείτε περισσότερες πληροφορίες στο σχετικό README στον φάκελο `src/main/java/edu/aueb/ds/datastructures`.

## Μέρος Β: Έλεγχos Ετικετών (Tags) HTML

### Στόχος

Τα αρχεία HTML χρησιμοποιούν ετικέτες (tags) για να ορίσουν τη δομή και το περιεχόμενο μιας ιστοσελίδας. Για να εμφανιστεί σωστά μια σελίδα, αυτές οι ετικέτες πρέπει να είναι σωστά "ισορροπημένες" και "εμφωλευμένες". Αυτό σημαίνει ότι κάθε ετικέτα που ανοίγει (π.χ. `<body>`) πρέπει να έχει μια αντίστοιχη ετικέτα που κλείνει (`</body>`) και οι ετικέτες πρέπει να κλείνουν με την αντίστροφη σειρά από αυτή που άνοιξαν (Last-In, First-Out).

Στο Μέρος Β, θα χρησιμοποιήσετε μία από τις δομές που υλοποιήσατε στο Μέρος Α για να γράψετε ένα πρόγραμμα που ελέγχει αν οι ετικέτες σε ένα αρχείο HTML ακολουθούν αυτούς τους κανόνες.

Μπορείτε να βρείτε περισσότερες πληροφορίες στο σχετικό README στον φάκελο `src/main/java/edu/aueb/ds/tagchecking`.

## Αρχιτεκτονική του Project

Η δομή των φακέλων του project ακολουθεί το πρότυπο Maven/Gradle που είναι καθιερωμένο στη βιομηχανία λογισμικού Java.

```
DS_exercise_1/
├── out/                  <-- Φάκελος για τα μεταγλωττισμένα αρχεία (.class)
├── src/
│   ├── main/
│   │   └── java/
│   │       └── edu/aueb/ds/
│   │           ├── datastructures/  <-- Υλοποιήσεις List, Stack, Queue
│   │           ├── netprofit/       <-- Εφαρμογή NetProfit
│   │           └── tagchecking/     <-- Εφαρμογή TagChecking
│   └── test/
│       ├── java/
│       │   └── edu/aueb/ds/
│       │       ├── netprofit/       <-- Tests για το NetProfit
│       │       └── tagchecking/     <-- Tests για το TagChecking
│       │       └── TestDataStructures.java
│       └── resources/
│           ├── net_profit_test_cases/
│           └── tag_checker_test_cases/
│
├── docs/                 <-- Φάκελος για το παραγόμενο Javadoc
```

-   **`src/main/java`**: Περιέχει τον κώδικα της εφαρμογής, οργανωμένο σε πακέτα.
-   **`src/test/java`**: Περιέχει τον κώδικα ελέγχου (tests).
-   **`src/test/resources`**: Περιέχει αρχεία που χρησιμοποιούνται από τα tests, όπως τα αρχεία εισόδου.

### Γιατί το όνομα `edu.aueb.ds`;

Η οργάνωση του κώδικα σε πακέτα (packages) είναι μια θεμελιώδης πρακτική στην Java. Το όνομα `edu.aueb.ds` λειτουργεί σαν μια **μοναδική διεύθυνση** για τον κώδικα του project.

**Ο κύριος λόγος είναι η αποφυγή συγκρούσεων.** Φανταστείτε ότι ονομάζετε μια κλάση `List`. Τι θα συνέβαινε αν χρησιμοποιούσατε μια εξωτερική βιβλιοθήκη που έχει επίσης μια κλάση με το όνομα `List`; Η Java δεν θα ήξερε ποια να διαλέξει.

Χρησιμοποιώντας ένα μοναδικό όνομα πακέτου, δημιουργούμε έναν ασφαλή "χώρο ονομάτων". Έτσι, η δική μας κλάση `edu.aueb.ds.datastructures.List` δεν θα μπερδευτεί ποτέ με μια άλλη κλάση `com.google.common.collect.List` από μια εξωτερική βιβλιοθήκη. Είναι ο τρόπος που διασφαλίζουμε ότι ο κώδικάς μας είναι οργανωμένος και ασφαλής για χρήση με άλλο κώδικα.

## Μεταγλώττιση και Εκτέλεση

Όλες οι παρακάτω εντολές πρέπει να εκτελούνται από τον κεντρικό φάκελο του project (`DS_exercise_1`).

### Βήμα 1: Μεταγλώττιση

Για τη μεταγλώττιση του project, χρησιμοποιήστε τις παρακάτω εντολές. Η πρώτη δημιουργεί τον φάκελο `out` όπου θα αποθηκευτούν τα αρχεία `.class` και η δεύτερη μεταγλωττίζει τον κώδικα της εφαρμογής και των tests.

1.  **Μεταγλώττιση του Κώδικα της Εφαρμογής:**
    ```bash
    javac -d out/production src/main/java/edu/aueb/ds/datastructures/*.java src/main/java/edu/aueb/ds/netprofit/*.java src/main/java/edu/aueb/ds/tagchecking/*.java
    ```

2.  **Μεταγλώττιση του Κώδικα Ελέγχου (Tests):**
    ```bash
    javac -d out/test -cp out/production src/test/java/edu/aueb/ds/*.java src/test/java/edu/aueb/ds/netprofit/*.java src/test/java/edu/aueb/ds/tagchecking/*.java
    ```

### Βήμα 2: Εκτέλεση των Tests

Μπορείτε να εκτελέσετε τους αυτοματοποιημένους ελεγκτές για κάθε μέρος της εργασίας.

-   **Έλεγχος Δομών Δεδομένων (Μέρος Α):**
    ```bash
    java -cp out/test:out/production edu.aueb.ds.TestDataStructures
    ```

-   **Έλεγχος Ετικετών HTML (Μέρος Β):**
    ```bash
    java -cp out/test:out/production edu.aueb.ds.tagchecking.TestTagChecking
    ```

-   **Έλεγχos Καθαρού Κέρδους (Μέρος Γ):**
    ```bash
    java -cp out/test:out/production edu.aueb.ds.netprofit.TestNetProfit
    ```

### Βήμα 3: Εκτέλεση των Εφαρμογών

Μπορείτε να εκτελέσετε τις εφαρμογές των Μερών Β και Γ δίνοντας ως όρισμα το κατάλληλο αρχείο εισόδου.

-   **Εκτέλεση TagChecking:**
    ```bash
    java -cp out/production edu.aueb.ds.tagchecking.TagChecking src/test/resources/tag_checker_test_cases/BC-01.html
    ```

-   **Εκτέλεση NetProfit:**
    ```bash
    java -cp out/production edu.aueb.ds.netprofit.NetProfit src/test/resources/net_profit_test_cases/TC-01_input.txt
    ```

## Πληροφορίες για την κατασκευή του Javadoc

Για να δημιουργήσετε την τεκμηρίωση Javadoc για το project, εκτελέστε την παρακάτω εντολή. Η τεκμηρίωση θα αποθηκευτεί στον φάκελο `docs/`.

```bash
  javadoc -d docs -sourcepath src/main/java -subpackages edu.aueb.ds
```

Για να δείτε την τεκμηρίωση, ανοίξτε το αρχείο `docs/index.html` με έναν browser.
