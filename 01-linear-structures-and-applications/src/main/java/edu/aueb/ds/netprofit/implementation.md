# NetProfit – Περιγραφή υλοποίησης

## Ο αλγόριθμος

Η λογιστική αρχή είναι **FIFO**: οι μετοχές που πουλάμε θεωρούνται αυτές που αγοράστηκαν πρώτες.
Για αυτό χρησιμοποιείται μία **ουρά (`Queue`)**, η `QueueImpl` του Μέρους Α.

* Κάθε εντολή `buy N price P` δημιουργεί μια **παρτίδα (`Lot`)** με τα πεδία
  `shares` (πόσες μετοχές της παρτίδας δεν έχουν πουληθεί ακόμα) και `price`.
  Η παρτίδα μπαίνει στο **τέλος** της ουράς (`put`).
* Κάθε εντολή `sell N price P` "αδειάζει" παρτίδες από την **αρχή** της ουράς:
  1. Κοιτάμε την παλαιότερη παρτίδα με `peek()`.
  2. Παίρνουμε `used = min(remaining, lot.shares)` μετοχές από αυτήν και προσθέτουμε
     στο συνολικό κέρδος `used * (P - lot.price)`.
  3. Μειώνουμε τα `lot.shares` και τα `remaining` κατά `used`.
  4. Αν η παρτίδα εξαντλήθηκε (`lot.shares == 0`) την αφαιρούμε με `get()`.
  5. Επαναλαμβάνουμε μέχρι `remaining == 0`.
* Στο τέλος τυπώνεται `Total net profit: <κέρδος>`.

Παράδειγμα (README): `buy 40@25.2`, `buy 30@21.8`, `buy 50@34.4`, `sell 100@30`
δίνει `40*(30-25.2) + 30*(30-21.8) + 30*(30-34.4) = 192 + 246 - 132 = 306`.
Στην ουρά μένουν 20 μετοχές της τελευταίας παρτίδας (ιδιότητα FIFO).

## Επιλογές υλοποίησης

* **Γιατί ουρά;** Η πρώτη παρτίδα που εισάγεται είναι η πρώτη που καταναλώνεται – ακριβώς η
  πειθαρχία FIFO. Στοίβα θα έδινε LIFO, δηλαδή λάθος αποτέλεσμα.
* **Τροποποίηση της παρτίδας "επί τόπου".** Η `peek()` επιστρέφει αναφορά στην παρτίδα, άρα όταν
  μια πώληση καταναλώνει μόνο μέρος της, απλώς μειώνουμε το `shares` χωρίς να βγάλουμε/ξαναβάλουμε
  την παρτίδα στην ουρά.
* **Μετρητής `available`.** Κρατάμε το συνολικό πλήθος διαθέσιμων μετοχών, ώστε ο έλεγχος
  "πουλάω περισσότερες από όσες έχω" να γίνεται σε O(1) και **πριν** αλλάξει οτιδήποτε:
  `Error: Attempting to sell X shares, but only Y are available.` και το πρόγραμμα τερματίζει.
* **Ακρίβεια αποτελέσματος.** Το κέρδος συσσωρεύεται σε `double` ανά παρτίδα με τη σειρά FIFO
  (`totalProfit += used * (price - lot.price)`), ώστε τα αποτελέσματα να ταυτίζονται ψηφίο προς
  ψηφίο με το `solutions.txt`.
* **Οριακές περιπτώσεις.** Αγορές με 0 μετοχές δεν εισάγονται στην ουρά· πώληση 0 μετοχών δεν
  κάνει τίποτα· γραμμές που δεν έχουν ακριβώς 4 λέξεις ή δεν έχουν τη μορφή
  `buy|sell <N> price <P>` αγνοούνται σιωπηλά.
* **Σφάλματα.** `IOException` → `Error: Could not read file '<path>'. <details>`,
  `NumberFormatException` → `Error: Invalid number format in the input file.`,
  και χωρίς όρισμα → `Usage: java NetProfit <path_to_text_file>`.

## Πολυπλοκότητα

Κάθε παρτίδα εισάγεται μία φορά και αφαιρείται το πολύ μία φορά, και κάθε βήμα του βρόχου
πώλησης είναι O(1) (`peek`, `get`, αριθμητικές πράξεις). Ο συνολικός χρόνος είναι
**O(n)** για n γραμμές εισόδου και η μνήμη **O(n)** στη χειρότερη περίπτωση (όλες αγορές).
Η ανάγνωση γίνεται με `BufferedReader`, άρα ακόμα και το αρχείο των ~4 MB (TC-20) τρέχει άμεσα.
